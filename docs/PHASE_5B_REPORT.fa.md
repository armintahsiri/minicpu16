آزمون ۱۲ جهش قدیمی (دقیقاً پیکربندی 5A) همهٔ ۱۲ مورد را در ستون هدایت‌شده شناسایی کرد:

```
1  register file reset gating removed
2  writes to R0 allowed
3  load-use stall for store DATA removed (rs2 match dropped)
4  taken branch flushes only IF/ID, not ID/EX
5  WB->ID write-through removed
6  LB uses zero extension instead of sign extension
7  SB byte-bank select swapped
8  misaligned LW uses the next word instead of aligning down
9  HALT does not flush younger instructions
10 JALR target uses the link value instead of old rs1
11 store->load same address returns the OLD value (distance 1)
12 UART write while busy is not dropped
=> 12/12 detected (directed, FORWARDING=false)
```

## ۳. زمان‌بندی جانبی روی کاغذ و لایهٔ زمان‌بندی (گام ۲)

تنها ناحیه‌ای که اجازهٔ اصلاح داشت، آیتم‌های جانبی بود. به‌همراه اشتقاق دستی روی کاغذ، بخش ۷ قرارداد (normative) اضافه شد:

- **۷.۱ TIMER** (`0xFF08`): خواندن در چرخهٔ MEM برابر `c` مقدار `c mod 2^16` را می‌دهد.
- **۷.۲ UART**: پنجرهٔ busy دقیقاً `N` چرخهٔ قابل‌مشاهده `c+1..c+N`؛ اولین idle در `c+N+1`. پذیرش نوشتن فقط اگر در چرخهٔ MEM خودش idle باشد.
- **۷.۳ GPIO_IN**: سینک دو-فلیپ‌فلاپ، `L=2`؛ خواندن در چرخهٔ MEM `c` مقدار `ext(c-2)` را می‌بیند.

**باگ واقعی RTL که در این گام پیدا و اصلاح شد (F25):** پنجرهٔ busy یک چرخه بلندتر از قرارداد بود. قرارداد + لایهٔ زمان‌بندی + تست‌های طلایی به‌روز شد و تست‌بنچ برگ `tb_mmio.vhd` با مرز دست‌اشتقاقی بازنویسی شد.

## ۴. معماری 5B روی کاغذ و تغییرات RTL (گام‌های ۳ و ۴)

شبکهٔ forwarding کامل پیاده شد (یافته‌ها در `docs/RTL_ARCH.md` بخش ۶–۹):

- تولیدکننده‌های `EX/MEM` و `MEM/WB`؛ **جوان‌ترین برنده** است: `EX/MEM` بر `MEM/WB` اولویت دارد.
- **load در `EX/MEM` forward نمی‌شود** → توقف load-use فقط در فاصلهٔ ۱.
- نوشتن همزمان WB→ID (write-through) حفظ شد.
- `R0` هرگز نه forward می‌شود و نه نوشته می‌شود.
- بیت‌های valid مانع forward از حباب یا دستورالعمل flush‌شده می‌شوند.
- پیش‌بینی استاتیک not-taken؛ انشعاب در EX resolve می‌شود.

پارامتر `FORWARDING` پیش‌فرض `true` شد؛ ۱۹ شمارندهٔ پوشش جدید (کل ۳۶) با helper `fwd_active` اضافه شد. `COV_N` از ۱۶ به ۳۶ رسید.

**فرمول دست‌اشتقاقی چرخه:**
```
total = N + 4 + S + 2·R
N = دستورالعمل‌های بازنشسته‌شده (شامل HALT)
S = توقف‌های load-use
R = انشعاب شرطیِ گرفته + JAL + JALR
```
این فرمول **هم توسط مدل طلایی و هم توسط RTL** برای هر ۱۱ بنچمارک با `fwd=True` دقیقاً منطبق شد.

## ۱۰. شبیه‌سازی پس از سنتز (گام ۱۰، اختیاری)

گام ۱۰ اختیاری بود، اما **اجرا شد**. ابزار جدید `tools/postsynth_sim.py` (و هدف `make postsynth-sim`):

1. برنامهٔ اختصاصی `tests/directed/l_postsynth.asm` (forwarding فاصلهٔ ۱، مصرف‌کنندهٔ I-type، توقف load-use، انشعاب روبه‌عقب گرفته، سپس ذخیره در GPIO_OUT).
2. نگاشت با Yosys + `ghdl-yosys-plugin`.
3. اجرای netlist با دستور داخلی `sim` یوسیس و استخراج VCD.
4. مقایسه با مدل طلایی.

**نتیجه:** `gpio_out` ورودی سطح‌گیت دقیقاً `0x0026` شد — منطبق بر طلایی — و HALT تأیید شد. `pc_out` (اشاره‌گر fetch داخلی) پس از HALT از نظر معماری نامشخص است (یافتهٔ F3)، بنابراین گزارش می‌شود ولی assert نمی‌شود.

**غیر-توخالی بودن اثبات شد:** با اعمال جهش ۱۶ روی یک کپی موقت RTL (غیرفعال‌کردن forwarding به عملوند B)، `gpio_out` روی سطح‌گیت به `0x0000` افت کرد و ابزار شکست خورد. پس این بررسی یک باگ واقعی forwarding را در منطق پس از سنتز می‌گیرد.

**یافتهٔ F31:** اجرای netlist سلولی iCE40 با مدل آزاد `cells_sim.v` کار نمی‌کند، چون مدل `SB_RAM40_4K` پارامترهای `INIT_*` را بار نمی‌کند و ROM صفر (HALT) خوانده می‌شود. netlist سنتزشدهٔ خودش درست است. به همین دلیل از نگاشت فناوری عمومی استفاده شد که حافظهٔ مقداردهی‌شده را حفظ می‌کند. این محدودیت مدل شبیه‌سازی است، نه RTL.

- **F28** — `fwd_from_bubble` و `stall_near_flush` عملاً همیشه صفرند.
- **F29** — تعریف چرخه و تخلیهٔ HALT.
- **F30** — تخمین‌های flat در nextpnr برای `FORWARDING=true` کمترند.
- **F31** — شبیه‌سازی پس از سنتز نیازمند نگاشت فناوری عمومی است.

هیچ‌کدام از این‌ها ISA را تغییر نداد.

## ۱۳. محدودیت‌ها و موارد صریحاً انجام‌نشده

برای شفافیت کامل:

1. **شبیه‌سازی پس از سنتز با netlist سلولی iCE40 کامل نشد**؛ به‌جای آن نگاشت فناوری عمومی اجرا شد (F31). `pc_out` در این بررسی assert نمی‌شود (F3).
2. **Fmax یک تخمین flat و تیون‌نشده است**، نه عدد sign-off. هیچ تیونینگی انجام نشد (غیر-هدف).
3. **خروجی فقط-fuzz برای ۳ جهش** (`False`) گزارش شده است؛ حذف یا پنهان نشد.
4. **دو برنامه (`05_mmio` و `hello`)** در رگرسیون معماری 5A به‌صورت طراحی‌شده کنار گذاشته شده‌اند (D37)، چون 5A دقیق‌چرخه‌ای نیست.
5. **برآوردهای what-if بخش ۹ فقط حسابی‌اند** و در سخت‌افزار اندازه‌گیری نشدند.
6. سنتز و فازینگ‌های سنگین در CI اجرا نمی‌شوند و به‌صورت محلی اجرا شدند.

**نتیجه:** همهٔ اهداف الزامی فاز ۵B (بستن بدهی‌های 5A، دقت چرخه‌ای کامل با forwarding، اندازه‌گیری صادقانهٔ Fmax/CPI) محقق شد و با برچسب `rtl-5b` روی همین کامیت نهایی تثبیت شد.
